# 設計判断の記録

## ADR-001：作品の正式データはFirestore、検索は再構築可能な投影

- 日付：2026-10-17
- 状態：仕様へ採用。実装未着手。
- 背景：既存の入力表→Firestore→Algoliaの運用を維持しつつ、検索費用と将来のAI検索を考慮する。作品を二つのDBで独立編集する運用は避けたい。
- 決定：Sheetsは入力表、Firestore `works`は作品・約300字要約の正本。Supabaseのカタログ／ベクトルは単方向で自動生成し、直接編集しない。履歴等の本人状態はSupabaseへ継続保存する。
- 同期：FirestoreトリガーのCloud Functions第2世代＋再試行＋版比較＋定期照合。API本体はCloudflare Worker。関数・ビルド等も月額予算へ算入する。
- 代案：Firestoreベクトル検索は今後比較可能。Firebase Wrapperはライブ読取であり、索引複製の代わりにしない。管理されたFirebase Extensionsの新規依存は終了予定を考慮し採用しない。
- トレードオフ：検索索引の結果整合、同期運用、Firestore読取・Functions費用が追加される。正式な詳細・公開状態は正本で確認する。
- 根拠：移行仕様書第16・17章。Firebase／Supabase公式資料のリンクは同章を参照。

## ADR-002：スマホ・iPad・PCは能力と画面幅で最適化

- 日付：2026-10-17
- 状態：仕様へ採用。実機試験未実施。
- 決定：compact／medium／expandedのレスポンシブ表示。銘柄判定を主条件にせず、幅・入力・向き・分割表示を使う。iPadの縦横・Split View・外付け入力を受入条件に加える。
- 根拠：移行仕様書第18章。

## ADR-003：PDF 2.15GBは非公開R2へ、SSDを優先コピー元にできる

- 日付：2026-10-17
- 状態：採用。2.15GBは利用者申告、SSDのパス・manifestは未取得。
- 決定：既存のworks/enterYYYY/種類/ID.pdfを維持。SSDは読み取り、R2へのコピー・SHA-256照合を行う。SSD自体を変更しない。
- 費用：R2 Standardの無料保管枠内になる見込み。全操作が無制限無料ではなく、追加保管量・API・DB・同期・AIを別々に測る。
- 根拠：移行仕様書第3・19章。

## ADR-004：AIによる管理は再実行可能なコマンドと仕様に残す

- 日付：2026-10-17
- 状態：仕様へ採用。管理コマンドは未実装。
- 決定：検証・取込・PDF移行・検索修復・要約・埋め込み・通知・費用確認を構造化結果、dry-run、再開方法付きで実装する。秘密情報やチャットの記憶に依存しない。
- 根拠：移行仕様書第19章。
