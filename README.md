# 探究アーカイブ PWA

松本県ヶ丘高校の生徒・教員向けに、探究作品の検索・閲覧・保存ができるWebアプリです。

**[アプリを開く](https://kenryo-tankyu-archive.pages.dev/welcome)**

## 主な機能

- Googleログインと利用登録の確認。未登録の学校アカウントは登録待ち画面となり、作品を閲覧できません
- タイトル検索、自然な文章での検索、カテゴリ・サブカテゴリ・入学年度・学科の条件候補、並び替え
- EmbedPDFによるPDF閲覧、資料切り替え、共有・ダウンロード
- お気に入り、コレクション、閲覧履歴・検索履歴の整理、端末へのPDF一時保存（2週間）
- AI要約と参照ページへの移動、関連する作品、日替わりのおすすめ
- お知らせ・端末内の未読管理、ライト／ダークテーマ、PWAインストールと更新・復旧
- 起動・PDFのローディングアニメーションと探究のヒント。PDF取得中に表示エンジンを並行起動

標準の表示順はお気に入り数、KRGP受賞、探究科・普通科の優先順です。作者名・カテゴリ名・PDF本文・要約は通常のキーワード検索対象に含めません。

スマホ・タブレット・PCに対応しています。検索履歴やライブラリは端末内キャッシュを活用して通信を減らし、ログアウトや利用者の切り替え時にキャッシュを破棄します。

## 技術構成

フロントエンドはReact・TypeScript・Vite、PDF表示はEmbedPDFを使用しています。認証・通知はFirebase、作品検索・いいね・履歴はSupabase、PDF保管はCloudflare R2、公開先はCloudflare Pagesです。データへのアクセスは認証・認可を行うAPIを経由します。

このリポジトリはPWAのフロントエンドです。管理サーバー、管理キー、本番作品PDFは含みません。

## ローカル起動

Node.jsは `.nvmrc` に指定された22系を使用してください。

```sh
npm ci
npm run dev -- --port 4173
```

`http://127.0.0.1:4173/welcome` を開きます。実ログインには `.env.example` を参考にFirebase Web設定を `.env.local` に設定し、別途APIサーバーを用意します。開発時のAPI転送先は `localhost:8787` です。

## 確認・ビルド

```sh
npm run format:check
npm run typecheck
npm run lint
npm run build
```

ブラウザテストは `npm test`、機能別テストは `package.json` の `test:*` を参照してください。公開API契約は `src/contracts` に管理側から生成します。

## 素材・ライセンス

画像の出典とハッシュは [config/assets-manifest.json](config/assets-manifest.json) に記載しています。画像や学校の作品の自由な再利用を許諾するものではありません。本リポジトリ全体への一括したOSSライセンスは付与していません。

カテゴリ画像は `public/images/categories/` のSVGに統一しています。単色・背景透過で、表示サイズは400×400です。今後のカテゴリ向けの `sports.svg`（スポーツ）と `entertainment.svg`（娯楽・文化）も同じフォルダに保存しています。カテゴリ用の旧PNGは配信対象から削除しました。

EmbedPDFはMITライセンスです。SDK・Worker・フォントを同一サイトから配信し、各ライセンスを配信資産に同梱しています。その他の依存ライブラリは各配布元のライセンスに従います。

管理者はアカウント設定の「表示を確認」から、教員・生徒と入学年度ごとの表示を確認できます。これは画面表示の確認用で、ログインしている本人の権限やデータは変更しません。

KRGP受賞作品は専用画面で開催年・賞・賞名から選択できます。開催年は入学年度＋1（2024年度入学→KRGP 2025）。PCは左側の選択欄、スマホは上部のチップを使い、作品と公開作品の件数を1回のAPIで取得します。

KRGPは初回に作品情報を全件取得し、条件変更・並び替え・追加表示は端末内で処理します。ログイン中のメモリに本人別で保持し、30分経過後の再表示または更新ボタンで再取得。自分のお気に入り操作は即時反映し、ログアウト時に破棄します。PDF本体は含みません。

## 本番・デモの運用

本番は現在のアプリURLを維持し、デモは別URL・架空データで動かす構成を推奨します。同じコードを使い、公開する版と接続先を分けます。今あるサンプル表示フラグだけでは本番APIとの分離はできません。

ブランチ、公開タグ、利用開始までの手順は [本番・デモ・開発の分け方](docs/release-workflow.md) を参照してください。
